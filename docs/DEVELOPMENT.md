# NEXUS — Development guide

## Repository layout

```text
nexus/
├── apps/
│   ├── api/        # Express 5 API (TypeScript, Zod, pino)
│   └── mobile/     # Expo SDK 58 app (React Native 0.88, Expo Router)
├── packages/
│   ├── shared/     # @nexus/shared: Zod schemas, Markdown helpers, merge rules
│   └── ui/         # @nexus/ui: design tokens and primitives
├── docker-compose.yml  # local Postgres 18 + MinIO (R2 stand-in)
└── turbo.json
```

## Requirements

- Node.js 24 LTS or newer, pnpm 10
- Docker Desktop (for local Postgres and MinIO, from Phase 3)
- Android Studio with Android SDK, NDK 27.1 and CMake 4.1.2 (for native Android builds)

## Getting started

```bash
pnpm install
cp apps/api/.env.example apps/api/.env
cp apps/mobile/.env.example apps/mobile/.env
```

Run the API:

```bash
pnpm --filter @nexus/api dev     # http://localhost:4000/healthz
```

Run the mobile app on an Android device or emulator:

```bash
cd apps/mobile
npx expo run:android             # builds the native app, installs it and starts Metro
```

`apps/mobile/android` and `apps/mobile/ios` are generated by `expo prebuild` and are not committed. Native configuration belongs in `app.json` and config plugins under `apps/mobile/plugins/`.

### Windows notes

- Keep the repository on a short path (for example `C:\dev\nexus`). React Native's C++ build produces very long object paths.
- The `withCmakeVersion` config plugin pins CMake 4.1.2 (Ninja 1.12.1), which supports paths over 260 characters. Install it from Android Studio's SDK Manager (SDK Tools, CMake) if it is missing.
- pnpm uses the hoisted node linker (`pnpm-workspace.yaml`), which the React Native native build needs on Windows.

## Scripts

| Command             | What it does                                    |
| ------------------- | ----------------------------------------------- |
| `pnpm dev`          | Runs every workspace's `dev` task               |
| `pnpm typecheck`    | TypeScript in strict mode across all workspaces |
| `pnpm lint`         | ESLint across all workspaces                    |
| `pnpm test`         | Vitest (api, shared, ui) and Jest (mobile)      |
| `pnpm format`       | Prettier write                                  |
| `pnpm format:check` | Prettier check (used in CI)                     |

Commits follow [Conventional Commits](https://www.conventionalcommits.org/) and are checked by commitlint.

## API contract snapshot

`packages/shared/test/__snapshots__/schemas.contract.json` holds the JSON Schema of every exported Zod schema. If a schema change makes the snapshot test fail, check that the change is intended (it alters what the API accepts or returns), then accept it and commit the updated snapshot with the change:

```bash
pnpm --filter @nexus/shared exec vitest run -u
```

## Database

Local development uses PostgreSQL 18 from Docker Compose. Migrations and the seed run as the owner (`DATABASE_URL_DIRECT`); the API connects as `nexus_api`, which row-level security applies to (`DATABASE_URL`).

```bash
docker compose up -d postgres
```

```bash
pnpm --filter @nexus/api db:migrate      # applies migrations; enables nexus_api login locally
```

```bash
pnpm --filter @nexus/api db:seed         # demo@nexus.example with the demo corpus
```

Changing the schema:

1. Edit the Drizzle schema in `apps/api/src/db/schema/`.
2. Run `pnpm --filter @nexus/api db:generate` to create the next migration in `apps/api/drizzle/migrations/`.
3. Add any hand-written SQL (triggers, grants, functions) to that file, with a `down` comment block.
4. Commit the schema change and the migration together. CI fails if the schema has changes with no migration.

Database tests run against a throwaway PostgreSQL 18 container (Docker must be running):

```bash
pnpm --filter @nexus/api test:db
```

## Load smoke test (k6)

`scripts/k6/sync-smoke.js` runs 10 virtual devices against `POST /v1/sync` for 30 seconds and fails if the sync p95 exceeds 800 ms. It signs in as the seeded demo user, so seed first and start the API with `RATE_LIMIT_STORE=memory` (ten sign-ins from one IP would otherwise hit the auth limit).

```bash
docker run --rm -v "$PWD/scripts/k6:/scripts" grafana/k6:latest run -e API_URL=http://host.docker.internal:4000 -e PASSWORD=$DEMO_PASSWORD /scripts/sync-smoke.js
```

`scripts/k6/sync-load.js` is the full load test (T-62): 50 virtual devices (10 accounts × 5
devices) each push a 100-op batch once a minute for 5 minutes; it fails if the sync p95 exceeds
800 ms or any request fails. It creates and verifies its own accounts, so the API must run with
`E2E_MODE=true`. CI runs it weekly and on demand in `.github/workflows/perf.yml`; the result is
posted as a run annotation and the k6 HTML report is uploaded as an artifact.

## Attachments and background jobs

`docker compose up -d` also starts MinIO (S3 API on `localhost:9000`, console on `localhost:9001`, login `nexus` / `nexus-dev-secret`) and creates the `nexus-attachments-dev` bucket. MinIO no longer publishes community images to Docker Hub, so the compose file and the tests use Chainguard's `chainguard/minio` build.

To upload from a phone during development, forward the storage port as well as the API port, because presigned URLs point at `localhost:9000`:

```bash
adb reverse tcp:9000 tcp:9000
```

With `ROLE=all` (the default) the API process also runs the job workers and registers the cron schedules in pg-boss (all times UTC): `backup.dump` 01:00, `accounts.purge` 02:00, `versions.prune` 03:00, `attachments.orphan-sweep` 03:30, `changes.compact` Sundays 04:00, `tokens.prune` 05:00, `account.deletion-reminder` 09:00, `exports.expire` hourly at :15, `audit.prune` monthly. Scheduled jobs use `DATABASE_URL_MAINT`, a role that bypasses row-level security. The nightly backup needs `pg_dump` on the server and `BACKUP_AGE_RECIPIENT`; without them it logs a warning and skips.

## Mobile features that need extra setup

- **Push notifications** register only in a development or production build with an EAS project id
  (`extra.eas.projectId`); without one, `registerForPush()` quietly skips and everything else works.
- **Universal links**: the files in `deploy/well-known/.well-known/` are served from
  `https://app.nexus.example/.well-known/`. Fill in the release signing fingerprint and Apple Team ID
  first (see `deploy/well-known/README.md`).
- **Export formats** are specified in [`docs/export-format.md`](export-format.md), with the JSON schema in
  [`docs/schemas/nexus-export.schema.json`](schemas/nexus-export.schema.json).
- New native modules since Phase 7 (Skia, image picker, document picker, file system, notifications,
  task manager, sharing, image manipulator) need a fresh native build: run `npx expo prebuild` and rebuild
  the APK before running on a device.

## End-to-end tests (Maestro)

Flows live in `apps/mobile/.maestro` (one per scenario T-47…T-54, plus links, search, collections
and tags, and Trash). Run them against the debug build with Metro running:

```bash
# API with E2E_MODE=true in apps/api/.env (never in staging or production)
cd apps/mobile && node .maestro/run.mjs --device <adb serial> [--only 01,04]
```

- The runner clears app data with `adb shell pm clear` before each flow. `--keep-driver` skips
  Maestro's driver reinstall (install `maestro-app.apk` and `maestro-server.apk` from
  `maestro-client.jar` once), for phones that need the driver exempted from an app freezer.
- CI runs the suite on an Android emulator: `.github/workflows/e2e.yml` (nightly, on demand, and
  on pushes that touch the suite). It tests a release APK built with `EXPO_PUBLIC_E2E=1`, so the
  JS bundle is embedded (no Metro, dev menu or LogBox) and `plugins/withE2ECleartext.js` allows
  plain HTTP to the API and MinIO on localhost. Failures show up as run annotations, including
  the text that was on screen, so the raw logs aren't needed.
- `emulator-only` flows (T-49, airplane mode) cut wireless adb, and `manual` flows (T-54) need a
  fingerprint; both are skipped unless passed with `--include`.
- **TECNO / XOS phones:** the system app freezer ("Hiber") freezes the Maestro driver while it runs
  in the background, so flows stall with `DeviceServerDied`. Battery "no restrictions" did not stop
  it on the KM6. Use another device, an emulator or CI.
